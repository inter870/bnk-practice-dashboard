# 포트폴리오 모바일 UI 근본원인

## 관련 경로

- 진입점: `app.py`
- KPI 렌더 함수: `app.py::render_portfolio_section`
- 섹터 카드 렌더 함수: `src/institutional/ui.py::_sector_driver_rows`, `market_regime_macro_radar_html`
- 섹터 점수 계산: `src/institutional/market_regime.py::_sector_tailwinds`
- 공통 표시 사전: `src/ui/korean_labels.py`
- 최종 CSS 계층: `src/ui/korea_os_theme.py::KOREA_OS_CSS`

## 실제 원인

### 포트폴리오 KPI

기존 화면은 `st.columns(4)` 안에 `st.metric` 네 개를 배치한다. 모바일 390px와 360px에서는 Streamlit이 한 열로 쌓아 가로 스크롤은 발생하지 않았지만, 768px에서 사이드바가 열린 상태에서는 본문 폭이 줄어 각 카드 폭이 약 97px가 되었다. 값 글꼴은 36px로 유지되어 `100,000,000원`과 시장 국면 값이 여러 줄로 갈라졌다. 이는 값 계산 문제가 아니라 범용 `st.metric`과 고정 4열 배치의 반응형 경계 문제다.

또한 총자산 입력을 읽을 때 `safe_float(value) or 기본값` 패턴을 사용해 유효한 `0`도 결측으로 취급했다. 입력값 해석 계층에서 `None` 또는 비정상 수치일 때만 기존 기본값을 쓰도록 분리해 `0원`을 그대로 표시한다. 포트폴리오 계산식은 변경하지 않는다.

### 섹터 환경 카드

섹터 카드는 범용 `.pi-card`, `.pi-rebalance-item`, `.pi-rebalance-top`을 재사용한다. 데스크톱의 `.pi-card { min-height: 252px; overflow: hidden; }`와 모바일의 범용 헤더/행 세로 전환이 섞이면서 390px에서 카드 한 항목은 약 243px, 세 항목은 약 513px까지 늘어났다. 섹터명과 점수도 모바일에서 서로 다른 줄로 강제되어 정보 밀도가 낮아졌다.

## 브라우저 선택 표시와 실제 UI의 구분

첨부 화면의 파란 반투명 영역과 원형 핸들은 모바일 브라우저의 텍스트 선택 오버레이일 가능성이 높다. 일반 렌더 캡처에서는 해당 배경이 재현되지 않았다. 따라서 전역 `user-select: none`은 적용하지 않는다. 실제 수정 대상은 카드 폭, 글꼴 크기, 행 배치와 overflow다.

## 점수·분류 검증

- 높은 점수일수록 우호적인 섹터 환경이다.
- 강세: 60점 이상
- 약세: 44점 이하
- 중립: 45~59점
- `_sector_tailwinds`는 점수 내림차순이며 카드도 기존 순서를 유지한 채 각 분류의 최대 3개를 표시한다.
- 현재 빈 강세 그룹은 분류 결과일 수 있으며 렌더링 오류로 임의 채우지 않는다.

## 계산과 표시의 경계

총자산, 현금, 현금 비중, 섹터 점수, 분류 임계값과 원본 영문 키는 변경하지 않는다. 금액/비중 포맷, 섹터명·요인 문구, 카드 구조와 반응형 CSS만 표시 직전에 변환한다.

## 수정 범위

- KPI 전용 3열/2열/1열 반응형 카드와 별도 시장 국면 요약 줄
- 섹터 환경 전용 표시 사전, empty state, 진행 표시와 모바일 카드 CSS
- 포맷·용어·임계값 보존·HTML 회귀 테스트
